# Browser interception ownership

Research checked on 2026-10-17 against [AB Download Manager integration](https://github.com/amir1376/ab-download-manager-browser-integration/blob/master/src/linkgrabber/DownloadLinkInterceptor.ts), its [MV3 adapter](https://github.com/amir1376/ab-download-manager-browser-integration/blob/master/src/linkgrabber/Manifest3DownloadLinkInterceptor.ts), and Chrome [downloads](https://developer.chrome.com/docs/extensions/reference/api/downloads) / [webRequest](https://developer.chrome.com/docs/extensions/reference/api/webRequest) documentation. AB's download-created path cancels browser transfers before handing them to the app. Its MV3 adapter cannot synchronously block a webRequest response. StrataFetch uses its own implementation and does not copy request cookies or headers.

Extension 0.2.6 observes request methods using non-blocking webRequest. An eligible identified GET download gets a persisted recovery recipe and browser cancellation immediately, concurrently with opening consent. It does not wait for known length, a network probe or user acceptance. External pause/resume handlers cannot continue a cancelled transfer. A confirmed cancellation is mandatory before committing a competing native transfer. Decline or failed native handoff restarts using downloads.download, which uses normal browser security/session behavior. The native app still validates its anonymous response after consent. POST and POST-origin redirect chains stay untouched. Request-map misses retain the old conservative pause/probe behavior rather than guessing the original method. Completed files may be adopted only after consent.

The downloads API fires when a download begins, so a brief browser history entry and initial bytes can precede cancellation. This implementation does not claim pre-request blocking, universal zero-byte interception, authenticated request replay, or equivalence to IDM's proprietary integration. Expiring/one-time links may require returning to the source page.

Run `node --test scripts/browser-tests.mjs` for state-machine regressions. Run `node scripts/test-browser-stream.cjs` from the repository root with Playwright available (`NODE_PATH` if needed) and an installed Edge executable; override STRATAFETCH_TEST_BROWSER for another Chromium executable. This launches only an isolated test profile and local HTTP server. The real extension/browser APIs cancel a chunked query-URL download, keep it stopped during consent, restart on decline and leave POST alone. Only the external native consent/ack endpoint is substituted; separate native tests cover the companion. This is not an end-to-end test of the user's Chrome profile or a store-origin bridge.

## 0.2.7 supersedes the fallback policy

The browser transfer is now cancelled, confirmed stopped and erased before opening consent. A metadata snapshot survives erasure; absence from browser history no longer signals an unsupported or missing handoff. Native Start/Cancel is the only choice. No resume/download call exists in the capture or recovery path. Recovery cleans up matching interrupted browser IDs and does not cancel an acknowledged native job or remove unrelated completed files. This replaces the prior pause/replay and completed-file adoption policy for new automatic captures.

The loaded extension ID must match both the Chrome native manifest and the host allowlist. A store-upload ZIP loaded unpacked has a path-derived ID because its development key is deliberately omitted. Repair the exact verified local origin; never add a wildcard or put a path-derived local ID into production store configuration.
